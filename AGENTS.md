# OmniCast Forever: notes for AI coding agents

- **Product rules (from the owner, not negotiable):** one bar only, so never add a second bar of any kind. The bar shows only what the character is actively doing right now. It must scale cleanly to any size: art keeps its proportions and never just stretches. Check `docs/ROADMAP.md` before proposing features.
- WoW addon for **WoW Forever** (retail Midnight engine running Classic content, Interface 16001). Read `docs/FOREVER_API_NOTES.md` before touching swing or cast logic. The combat log is blocked and secret values apply in combat.
- The addon lives at the repo root (TOC + Lua files; the repo root is the CurseForge package root). The TOC load order matters. Modules are created with `ns:NewModule(name)`, get `Init()` on ADDON_LOADED and `Enable()` on PLAYER_LOGIN, and register events through `ns:On(event, fn, unit)`.
- Data flow: `Cast`/`Swing`/`TestMode` produce *lane* tables (`state`, `start`, `finish`, `color`, `label`, `icon`, `reverse`, `latency`, `queue`, `ticks`, ...). `Bar:BuildView` picks main lanes and an optional strip, and `RenderLane` draws them. The bar redraws a lane's fixed parts (colour, label, target) only when the lane table, `lane.serial` or `Bar.gen` changes. **Any producer that changes those fields must bump `lane.serial`.** Settings changes bump `Bar.gen` through `ApplySettings`. The update loop sleeps while idle and wakes on any game event or `ns:Wake()`, so call `ns:Wake()` when starting activity outside an event, such as from a slash command.
- Cast/stop/interrupt/fail handlers match by cast GUID (`SameCast`); state-based checks are only the fallback when GUIDs aren't readable.
- Edit Mode (`EditMode.lua`): read Blizzard's Edit Mode state and post-hook only. Never write to `EditModeMagnetismManager`/`EditModeManagerFrame` tables, because that taints Edit Mode and causes blocked actions. Two exceptions are designed by Blizzard for addon callers: `ClearSelectedSystem()`, which runs through a secure delegate out of combat, and `SetHasActiveChanges(true)`, which strips taint from its argument. OmniCast's Edit Mode changes are pending until Save; Revert, and leaving without saving, restore the snapshot taken on entry. Some Blizzard buttons are bound to the original function at load (`GenerateClosure`), so hook the button's click as well as the method.
- Never call `Show`/`Hide`/`SetParent` on Blizzard frames from addon code: the cast bar and swing timers are bottom-managed frames, and their OnHide re-lays out the protected action bars (taint, "blocked from an action"). Use alpha instead (`Blizzard.lua`).
- Never compare or do arithmetic on values from the game in combat without going through `ns.Compat` guards.
- When creating a new version, install it directly with `./build.ps1 -Bump patch -Install`. That copies the package into `D:\Battlenet\World of Warcraft\_forever_\Interface\AddOns\OmniCast_Forever`. The user has approved this, since development happens only on this machine, so they don't copy it by hand. Tell them to `/reload` in game afterwards.
- Commit each new version on `main` once it is built and installed, with a message naming the version (e.g. "Add queued spell display (v0.5.0)"). The user has approved this. Don't push or tag unless the user says to (see Releasing).
- Versions stay at 0.x.x. Bump the version with `./build.ps1 -Bump patch|minor`, which edits the TOC. Run `npm run check` (luaparse, Lua 5.1) after editing Lua.
- The user play-tests live. Their client is at `D:\Battlenet\World of Warcraft\_forever_`, and the saved log is in `WTF\Account\*\SavedVariables\OmniCast_Forever.lua`. Read it after sessions.
- Logging is off by default (v0.9). The user turns it on with `/oc log`. `ns:Log` lines are only recorded while it is on, so remind them to enable it before a test session.
- **Releasing (public, CurseForge):** the dev loop is: change, `./build.ps1 -Bump patch -Install`, the user tests with `/reload`, commit locally. When the user explicitly says to release, push `main` and a version tag to GitHub (github.com/Popidge/OmniCast_Forever); CurseForge packages every pushed tag through a webhook and `.pkgmeta`, and a GitHub Action attaches the zip to a GitHub release. A tag containing `beta` (e.g. `v0.9.1-beta`) is released as Beta, `alpha` as Alpha. Before tagging, write `CHANGELOG.txt` (player-facing notes for that version only) and the detailed `CHANGELOG.md` entry. Never push or tag without an explicit instruction. New addon files must sit at the repo root, and any new dev-only file must be added to the `.pkgmeta` ignore list.
